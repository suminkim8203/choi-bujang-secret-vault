# 켈비 학원 Windows PC 인수인계

**최신 정정 — 2026-10-27:** 공식 R7 설치 준비 묶음이 공개돼 있으며, 현재 정규 과제 제출에는 설치 묶음이 필수가 아닙니다. 이 문서는 Windows 설치형 제품을 선택할 때의 안내입니다. [현재 제출 경로와 R7 검증](FINISH_SUBMISSION_ROUTE.md)을 우선합니다. 아래의 예전 네 파일 포장·제출 보류 절차를 현재 정규 과제의 필수 제출 요건으로 읽지 않습니다.

2026-10-27 사용자는 학원 Windows PC를 사용할 수 있다고 답했고 아래 세 명령의 결과도 보고했습니다. 에이전트가 해당 PC를 직접 조작·검증한 결과는 아니며, 사용자 보고와 향후 준비 절차를 구분합니다. **UI 수정과 최종 제출은 보류 상태입니다.**

## 사용자가 보고한 현재 결과

- Node.js: `v24.19.0`.
- Windows PowerShell: `5.1.26100.9711`.
- 지정 실행 환경 폴더의 Test-Path 결과: `False`.

Node.js는 제공 문서의 수업 기준과 같습니다. False는 현재 사용자 프로필의 지정 폴더를 찾지 못했다는 결과이며, 담당자의 승인 실행 환경 준비 안내가 필요합니다. 다른 계정이나 다른 PC의 설치 상태를 추정하지 않습니다. Windows에서 실제 포장 명령을 실행한 것은 아니므로 `PROVIDED_RUNTIME_NOT_INSTALLED` 오류가 발생했다고 기록하지 않습니다.

다음은 담당자가 안내하는 승인 실행 환경의 준비 경로를 확인하는 일입니다. 임의로 폴더만 만들거나 다른 실행 파일을 복사해 설치 완료로 처리하지 않습니다. 승인 host의 존재·서명·유효성도 이 세 결과로 확인된 것은 아닙니다.

## 먼저 확인할 세 가지

학원 Windows PC의 PowerShell에서 아래 항목을 각각 확인합니다. 버전과 true/false만 확인하며 설정 파일·인증서·키·전체 개인 경로를 채팅에 붙이지 않습니다.

```powershell
node --version
$PSVersionTable.PSVersion.ToString()
Test-Path -LiteralPath (Join-Path $env:USERPROFILE '.aleph-alekov-host\runtime') -PathType Container
```

- 제공 문서는 Node.js 22~24를 안내하며 수업 기준은 24.19.0입니다. 명령을 찾지 못하면 임의 설치하지 말고 학원 담당자의 준비 상태를 확인합니다.
- 마지막 결과가 false면 담당자의 승인 실행 환경 설치 안내가 필요합니다.
- true는 폴더가 있다는 뜻일 뿐 유효한 서명·승인·실행 가능성을 입증하지 않습니다. 공식 도구가 실행 환경을 별도로 검증해야 합니다.
- Mac에서 확인한 `PROVIDED_RUNTIME_NOT_INSTALLED`를 Windows에서도 발생한 오류처럼 전달하지 않습니다.

지금은 Windows 환경 확인과 담당자 안내 확보까지 준비할 수 있습니다. 프로젝트의 최종 파일을 옮기거나 설치 묶음을 만들기 전에 새 UI 적용·검증과 최신 소스 저장점을 맞춥니다. 예전 공개 브랜치나 이전 제출물을 최신 작업본으로 간주하지 않습니다.

## 최종 UI 이후의 공식 포장·설치 순서

아래는 제공 `on-client/docs/PACKAGE_APP.md`의 절차이며 **지금 실행한 명령이 아닙니다**.

1. 새 UI에 맞춰 기능과 문서를 확인하고 정확한 최신 커밋으로 저장점을 정합니다. 비밀·개인 설정은 제외합니다.
2. 그 저장점의 프로젝트를 별도의 새 경로에 준비하고, 원본·학생 파일·제공 파일을 보존합니다. 필요한 운영 인증정보를 소스·ZIP·채팅으로 복사하지 않습니다.
3. 담당자가 준비한 승인 실행 환경과 host 안내를 확인합니다. 누락·서명 오류를 다른 패키지 형식이나 보안 설정 해제로 우회하지 않습니다.
4. 최종 UI에서 확정한 아이콘을 공식 도구의 조건으로 검사합니다. 아이콘 필드가 없으면 256×256, 8비트 RGB/RGBA, 비인터레이스 PNG 입력이 필요합니다.
5. `on-client`에서 제공 포장 도구의 `--finish-materials` 경로로 새 출력 폴더에 묶음을 만듭니다. UI가 미확정인 지금은 실행하지 않습니다.
6. 같은 실행에서 만들어진 `finish.commit.raw`, `finish.archive.tar.gz`, `app.zip`, `APP_PACKAGE_MANIFEST.json`을 서로 섞지 않고 보존합니다.
7. 생성된 `INSTALL.md`를 따라 또 다른 새 경로에 설치하고, 승인 host의 바로가기로 켭니다. 실제 설치 화면에서 선택한 기능과 UI가 보이는지 확인합니다.
8. 같은 버전의 실제 앱 화면과 시연 근거를 준비합니다. 브라우저 개발 화면을 설치형 앱 검증 화면으로 바꾸어 적지 않습니다.
9. **이 단계까지 마쳐도 업로드·평가 요청·최종 제출하지 않습니다.** 사용자의 명시적인 제출 지시를 기다립니다.

미커밋 상태는 `PACKAGE_FINISH_COMMIT_REQUIRED`, 승인 실행 환경 누락은 `PROVIDED_RUNTIME_NOT_INSTALLED`처럼 각각 다른 원인입니다. 담당자에게는 실제 해당 PC에서 관찰한 코드와 단계만 전달합니다. 인증정보 원문이나 개인 파일을 보내지 않습니다.
