# 켈비 16단계 구현·검증

확인일: 2026-10-20. 현재 공식 안내: https://aleph-omega.vercel.app/defense

## 변경·보존

시작 저장점은 `5abd4dd67af5ec56160f6615e06590914d40a13a`입니다. `on-client/student/extension.mjs`의 renderStatus를 구현하고, 공식 지시대로 renderEvents의 상세 안에 미지원 조치 안내만 더합니다. 13·14단계 함수와 15단계의 정렬·필터·상세 동작은 유지하며 17단계 이후 학생 함수, 제공 public/app.js·서버·인증·기존 방어전/XDR·DB 설정을 바꾸지 않습니다. 옛 제출 묶음과 루트 단계12 설정도 보존합니다.

| notifications | resource/code/message를 항목별 텍스트 표시, 빈 알림과 미확인 분리 | 실제 기기·기록·통신 알림, 빈 알림 모의 검사 |

세션은 현재 검증된 연결 한 개이며 과거 전체 목록이 아니라고 표시합니다. 기기 상태 unknown을 정상으로 바꾸지 않습니다. 원천 점검 결과를 악성코드 검사·치료·실제 조치 집행으로 보고하지 않습니다.

## 실행 결과

- `node --test test/stage13-identity.test.mjs test/stage14-decision.test.mjs test/stage15-events.test.mjs test/stage16-status.test.mjs`: 29개 통과. 단위 검사에는 최소 DOM 대역과 합성 입력만 사용합니다.
- `npm run check --prefix on-client`와 `git diff --check` 통과.
- 원본270파일의 시작 해시와 대조합니다. 앱 변경 범위는 위 두 함수의 지정 부분뿐입니다.
- 1280×720 실제 예제 화면에서 기기 unknown과 세션 active, 기기·보안 기록 알림을 확인했습니다. 제공 「도움정보 불러오기」를 직접 눌러 진단 여섯 필드가 학생 칸에 나타났고 「도움정보 복사」를 눌러 복사 완료 표시를 확인했습니다. 실제 클립보드 내용을 읽지는 않았습니다. 복사되는 값은 합성 clipboard.writeText 대역으로 검사했습니다.
- 자신이 실행한 예제 서버만 종료한 뒤 다시 불러오기와 제공 진단 조회를 직접 눌렀습니다. 기기·세션·진단 각각의 통신 실패와 자료별 알림·수동 재시도 안내, 학생 복사 비활성을 확인했습니다.
- 예제 서버를 재실행하고 같은 두 버튼을 직접 눌렀습니다. 이전 실패 안내가 제거되고 기기/세션·진단 여섯 필드와 복사 활성 상태로 돌아왔습니다. 자동 재시도를 추가하지 않았으며 학생 함수에 API 호출·타이머가 없음을 확인했습니다. 실제 네트워크 전체 횟수를 계측한 결과로 주장하지 않습니다.

## 재현·한계

macOS 저장소 루트에서 `ON_PORT=5190 npm run demo --prefix on-client` → http://127.0.0.1:5190/ 보호 현황 → 제공 진단 조회 → 학생 복사. 서버를 종료하고 직접 다시 불러오기/진단 조회 → 실패 확인 → 서버 재실행 → 같은 버튼을 직접 눌러 복구 확인합니다.

Node.js v24.10.0이며 공식 실행 안내22~24 범위 안입니다. 고정 검수24.19.0에서는 실행하지 않았습니다. 빈 목록·시간 초과·미지원 조치·민감 필드가 섞인 입력은 운영 설정을 바꾸지 않고 단위 검사로 확인했습니다. 실제 엔진·계정·AI 연결·조치는 미구성이며 예제 성공과 구분합니다. 학생 직접 실행 확인은 받지 않았고 브라우저 검증은 에이전트 수행입니다.

현재 포털은 17단계가10월26일 준비 중이며 이 반은16단계까지만 공개된다고 안내합니다. 16단계 판정 후 상태를 다시 확인하며, 단계 잠금을 우회하거나 운영 준비 전 AI 연결을 다른 방법으로 대체하지 않습니다. 공식 제출·판정은 아직 전입니다.
