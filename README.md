### 제작2: 공격 패턴 목록

공식 과제 창의 제작2 안내를 다시 읽고, [MITRE T1110](https://attack.mitre.org/techniques/T1110/), [T1110.003](https://attack.mitre.org/techniques/T1110/003/)과 [T1110.001](https://attack.mitre.org/techniques/T1110/001/) 원문을 확인했습니다. `xdr/brute-force/patterns.json`은 최신 여섯 항목이며 각 항목에 이름·조건·근거·출처·한계가 있습니다. 아래 수치는 실습용 선택이며 공식 채점 기준이나 MITRE 표준 수치가 아닙니다.

| 패턴 | 필요한 증거 | 자동으로 맞추지 않는 사례 |
|---|---|---|
| 같은 주소·계정의 반복 실패 | 동일 주소/계정으로 집계됐다는 확인, 실패20회 이상, 집계 범위180초 이내 | 몇 번의 실패, 집계 시간 없음, 주소/계정 상관관계 미확인 |
| 여러 계정에 같은 비밀번호 대입 | 동일 주소 확인, 서로 다른5계정 이상, 같은 비밀번호 대입이라는 확인 | 공유 주소만 같음, 여러 계정만 있음, 비밀번호 동일 여부 미확인 |

`match-patterns.mjs`는 확인된 관찰값을 조건에 대조해 패턴 ID만 반환합니다. 비밀번호 값을 받지 않고 동일 여부만 사용합니다. `observe.mjs`가 공식 가상 경보의 설명과 집계 메타데이터에서 이 관찰값을 만듭니다. ZTNA 요청 계약과는 다른 내부 자료형입니다. 규칙 수준만으로 공격을 결정하지 않으며, 증거 부족으로 매칭이 없는 경우도 정상 판정으로 단정하지 않습니다.

재현: `npm run test:xdr`. 패턴 조건, 정상 경보, Jev 실패/오류/시간 초과와 경계값, 거부 규칙 만료·주소 범위, 기존 판정 보존을 검사했습니다. 전체53개 검사가 통과했고 공식28건 실행 결과도 생성했습니다. a5006ef와79396cf 모두 실제0/100·X01_CLEAR_NOT_BLOCKED였습니다. 다음 재판정은 확인 후 기록합니다. 원본 시험 자료·자료실 API·기존 판정기 규칙은 변경하지 않았습니다.

## 현재 구현

## 실제 API 계약

| 경로 | 메서드 | 정상 응답 |
|---|---|---|
| /api/notes | GET | 로그인 사용자의 `{id,title,body}` 메모 배열 |
| /api/notes | POST | `{id?,title,body}` 입력; ID는 UUID, 생략 시 서버 생성; HTTP201 `{id}` |
| /api/notes/:id | GET | `{id,title,body}`; 없는 메모 HTTP404 |
| /api/notes/:id | PUT | `{title,body}` 입력; 수정한 `{id,title,body}` |
| /api/notes/:id | DELETE | 삭제한 `{id}`; 이후 같은 ID의 GET은 HTTP404 |

모든 메서드는 유효한 Bearer 토큰을 요구합니다. Vercel rewrite가 /api/notes/:id를 api/note.js로 연결합니다. 허용 경로 목록은 구현 경로의 기록이며, 그 목록 자체가 인증 검사를 대신하지 않습니다.
